# Experimental CCXT public spot preview

This is the first stage of the proposed CCXT architecture, not the complete implementation. The existing production adapters remain unchanged. The endpoints are disabled by default, and the CCXT adapter is never constructed while disabled. No API keys or wallet credentials are used.

The allowlisted public interface supports Kraken and Coinbase, BTC/USD, ETH/USD, BTC/USDT and ETH/USDT. Each provider must return matching active spot metadata and a provider market identifier. Tickers require a positive price and provider timestamp at most 15 minutes old. Candle previews require a bounded, aligned, consecutive and fresh closed-candle window. Invalid or unsupported results are rejected; fallback retains the exact symbol and quote. Responses disclose provider, provider market ID, retrieval time and sanitized previous failures. Provider endpoint URLs and independent authenticity are not established by this adapter.

[CCXT 4.5.91's Kraken ticker parser](https://github.com/ccxt/ccxt/blob/v4.5.91/python/ccxt/kraken.py) sets the unified ticker timestamp to `None`; therefore that ticker is rejected with `provider_timestamp_missing` and the exact-quote Coinbase fallback may be used if its own timestamp and market identity pass validation. This is a known adapter behavior, not proof that every Kraken failure has this cause. Retrieval time is never substituted for a provider observation time.

Use `CIN_CCXT_PREVIEW_ENABLED=1` only on an isolated test service after the pinned `requirements-ccxt.txt` dependency is installed. Its routes are `GET /research/ccxt/ticker?symbol=BTC%2FUSD` and `GET /research/ccxt/candles?symbol=BTC%2FUSD&interval=1h&limit=24`. The public order-book preview is `GET /research/ccxt/order-book?symbol=BTC%2FUSD`; it returns up to ten bid and ask levels, with explicit base-quantity and quote-price units and a midpoint spread. It rejects malformed or crossed books. A missing provider timestamp is reported as unknown freshness, and the book is never eligible for automated liquidity conclusions in this preview. The default providers are Kraken then Coinbase; an unsupported, unavailable, stale or invalid result does not become research evidence. The preview has a single in-process request gate, a bounded queue of four requests with a 20-second wait, and a per-provider process-local operation budget; CCXT's per-instance rate limiter is enabled and reused. This is not a distributed rate limiter and upstream market-loading can make additional HTTP requests. Availability, data quality and resource costs must be independently tested on Render before activation. If Render's build command is configured manually, it must install both `cin/requirements.txt` and `requirements-ccxt.txt`.

Only public methods are invoked: market metadata, ticker, OHLCV and order-book observation. No public HTTP route exposes a raw exchange object, arbitrary CCXT method, private account, order or wallet operation. Tests use injected fake public exchanges and never transmit data.

The optional `GET /research/ccxt/closed-candle-comparison?symbol=BTC%2FUSD` compares independently validated 1h spot candle closes from Kraken and Coinbase only when both report the same close window. Partial responses and mismatched windows contain no calculated difference. This is historical research, not a live ticker or executable opportunity; analysis eligibility remains false.

WebSockets, derivatives, history pagination, live cross-exchange comparison, shared request budgets, monitoring, comprehensive caching, production fallback and dashboard integration are not implemented by this preview. A provider response is not evidence of a reliable prediction or a qualifying shortlist.

## Process-local provider observations

The optional `GET /research/ccxt/provider-observations` reports the last accepted and rejected public operations and their local elapsed time. It reads memory only: it neither contacts exchanges nor initializes CCXT. Counts and observations reset on restart and are not shared between workers. A rejection may be a data-quality rejection rather than a provider outage. An accepted order-book observation does not mean its provider timestamp is known or that it is eligible for automated analysis. This is not uptime monitoring or an independent health probe.

## Bounded public trade-stream experiment

`GET /research/ccxt/public-trades-stream?symbol=BTC%2FUSD` is an experimental server-sent event (SSE) preview backed by a public Kraken CCXT WebSocket. It is separately disabled unless both `CIN_CCXT_PREVIEW_ENABLED=1` and `CIN_CCXT_STREAM_ENABLED=1`. It accepts only BTC/USD and ETH/USD spot markets with verified matching active metadata and makes no authenticated calls. It does not submit or manage orders.

A `connected` event means only that the stream is set up; no trade is implied. A `trade` event is emitted only for a public trade received after the connection, with a nonempty ID, the exact symbol, finite positive price and quantity, and a nonfuture provider timestamp no more than 30 seconds old. Duplicate IDs are suppressed. Provider time and identity are not independently verified. Invalid, stale or missing data is omitted; unavailable connections and timeouts do not generate synthetic trades. This is an experimental observation stream, not a forecast or an eligible shortlist input.

The preview allows one stream per process, at most 120 events or 120 seconds after connection, a 30-second per-process cooldown, bounded caches, a connection timeout, and close on completion or disconnect. These limits are not distributed across workers or a substitute for provider-specific usage limits. The browser dashboard is not wired to this route. Stage on the test service and validate that the host permits public WebSocket egress, that close/disconnect works, and that free-tier resource use is acceptable before considering integration.
