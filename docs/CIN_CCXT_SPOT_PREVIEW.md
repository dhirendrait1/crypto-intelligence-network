# Experimental CCXT public spot preview

This is the first stage of the proposed CCXT architecture, not the complete implementation. The existing production adapters remain unchanged. The endpoints are disabled by default, and the CCXT adapter is never constructed while disabled. No API keys or wallet credentials are used.

The allowlisted public interface supports Kraken and Coinbase, BTC/USD, ETH/USD, BTC/USDT and ETH/USDT. Each provider must return matching active spot metadata and a provider market identifier. Tickers require a positive price and provider timestamp at most 15 minutes old. Candle previews require a bounded, aligned, consecutive and fresh closed-candle window. Invalid or unsupported results are rejected; fallback retains the exact symbol and quote. Responses disclose provider, provider market ID, retrieval time and sanitized previous failures. Provider endpoint URLs and independent authenticity are not established by this adapter.

Use `CIN_CCXT_PREVIEW_ENABLED=1` only on an isolated test service after the pinned `requirements-ccxt.txt` dependency is installed. Its routes are `GET /research/ccxt/ticker?symbol=BTC%2FUSD` and `GET /research/ccxt/candles?symbol=BTC%2FUSD&interval=1h&limit=24`. The default providers are Kraken then Coinbase; an unsupported, unavailable, stale or invalid result does not become research evidence. The preview has a single in-process request gate, a bounded queue of four requests with a 20-second wait, and a per-provider process-local operation budget; CCXT's per-instance rate limiter is enabled and reused. This is not a distributed rate limiter and upstream market-loading can make additional HTTP requests. Availability, data quality and resource costs must be independently tested on Render before activation. If Render's build command is configured manually, it must install both `cin/requirements.txt` and `requirements-ccxt.txt`.

Only public methods are invoked: market metadata, ticker and OHLCV. No public HTTP route exposes a raw exchange object, arbitrary CCXT method, private account, order or wallet operation. Tests use injected fake public exchanges and never transmit data.

WebSockets, order books, derivatives, history pagination, cross-exchange comparison, shared request budgets, monitoring, comprehensive caching, production fallback and dashboard integration are not implemented by this preview. A provider response is not evidence of a reliable prediction or a qualifying shortlist.
